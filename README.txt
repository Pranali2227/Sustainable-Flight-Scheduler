NORTHSTAR AIRLINE LOGISTICS - ORACLE CONNECTED VERSION

The browser page reads Oracle data through the local FastAPI service. Page
changes are committed to Oracle. Changes made in Oracle SQL Developer appear
in the page on the next refresh (automatic refresh every 5 seconds).

SET UP
1. Install Python 3.10 or newer.
2. From this folder, install dependencies:
	py -m pip install -r requirements.txt
3. Copy .env.example to .env.
4. Edit .env with the Oracle schema username, password, and service DSN.
	Use the service where your tables were created. This project uses
	localhost:1521/XE because its tables are in CDB$ROOT; XEPDB1 is a
	separate container and does not contain these tables.
5. Start the service from this folder:
	py -m uvicorn server:app --reload --host 127.0.0.1 --port 8001
6. Open http://127.0.0.1:8001 in the browser. Do not open index.html directly.
7. On first use, choose Create an account and register with your name, email,
   and a password of at least 10 characters. Later, sign in using that account.
8. Use the sign-out button at the bottom of the sidebar when finished.

Accounts are stored in a separate APP_LOGIN_USERS table, not the existing
subscription-oriented USERS table. The app creates APP_LOGIN_USERS when needed
and stores scrypt password hashes, never plaintext passwords. Sessions use a
signed HttpOnly cookie that expires after 12 hours. Keep .session_secret private;
it is excluded from Git. Deleting that file signs out every active session.

The API uses python-oracledb's Thin mode; Oracle Instant Client is not needed
for standard TCP Oracle XE connections. Keep .env private; it is excluded from
Git by .gitignore.

DATABASE NOTES
The API maps the page's flights, aircraft, crew, cargo, passengers, disruptions,
and emissions views to FLIGHT, AIRCRAFT, CREW, SPEC_CARGO, PASSENGER,
DISRUPTION, and EMISSIONS. Flight, crew, and passenger display fields include
derived values from related tables. Editing a record only changes the mapped
base-table fields; foreign-key values are chosen from current Oracle records.

Before using Add, check that numeric primary keys are generated by identity
columns, column defaults, or insert triggers. The provided column and
constraint reports do not show key-generation behavior. If keys are not
generated, create sequences/triggers in Oracle or extend the add forms to
request explicit IDs. Oracle constraints remain authoritative for all writes.

GET /api/health reports Oracle connectivity. Operational data and CRUD routes
require a signed-in account. All registered accounts currently have the same
access; there are no separate administrator/operator roles. The API is intended
for localhost coursework use; do not expose it to an untrusted network.
